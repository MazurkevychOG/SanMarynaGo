# SanMarynaGO — каталог місць

Статичний сайт для GitHub Pages: список місць, карта, фільтр, вибір місць для маршруту (час і відстань), перегляд фото.
Дані лежать у репозиторії як файли, а не вшиті в `index.html`. На самому сайті місця можна додавати, змінювати, видаляти й упорядковувати,
але ці зміни зберігаються **лише в браузері** і в репозиторій не потрапляють, поки ви не вивантажите файл обміну (розділ нижче).

## Структура

```
index.html                 сайт: читає каталог із data/, ваші зміни зберігає лише у браузері (IndexedDB / localStorage)
sw.js                      service worker: офлайн-режим (див. «Офлайн і оновлення»). Має лежати поруч з index.html
apple-touch-icon.png       іконка для «Додому» на iPhone
data/
  index.json               легкий список для карти й списку (будується скриптом)
  types.json               довідник типів місць: пляж, ресторан, екстрім, винарня… (id, назва, значок)
  places/<id>.json         одна картка = один файл (єдине джерело правди)
  photos/<id>/NN.webp      фото до 1600 px (WebP), NN_thumb.webp — мініатюра; NN.mp4 — відео без перекодування
  users/<id>.json          особисті кабінети: паливо, збережені маршрути, налаштування екрана (з'являється після першого експорту)
  users/index.json         список користувачів (будується скриптом)
schema/                    JSON Schema: place.schema.json, types.schema.json, user.schema.json
scripts/                   add-place, update-place, import-bundle, build-index, validate, fill-near, migrate
inbox/                     сюди завантажують файл обміну — Action сам додасть його в каталог
migration/                 вихідна копія даних до переходу на каталог (places.original.json.gz) і таблиця id (slugs.json)
.github/workflows/validate.yml         перевірка на кожен push і pull request
.github/workflows/import-inbox.yml     імпорт файлів обміну з inbox/ (комітить результат сам)
.github/ISSUE_TEMPLATE/new-place.yml   форма «Нове місце»
github-setup/              запасні копії файлів `.github/` (див. нижче — це важливо)
```

## ⚠️ Одноразове налаштування GitHub (без нього файли з `inbox/` не імпортуються)

1. **Папка `.github/` має бути в репозиторії.** Папки з крапкою на початку часто **не потрапляють** при завантаженні через веб-інтерфейс
   (їх ховає Finder/Провідник і пропускає «перетягування»). Перевірте на github.com: чи є `.github/workflows/import-inbox.yml`.
   Якщо ні — створіть файли вручну за інструкцією в `github-setup/README.md` (це 3 копіювання тексту).
2. **Settings → Actions → General → Workflow permissions → Read and write permissions → Save.** Інакше робот не зможе закомітити результат.
3. **Settings → Pages**: Source — Deploy from a branch → `main` / `(root)`.
4. Перевірка: вкладка **Actions** має показувати «Імпорт файлів обміну з inbox/» і «Перевірка каталогу». Імпорт можна запустити й вручну:
   Actions → «Імпорт файлів обміну…» → **Run workflow**.

## Поля картки (`data/places/<id>.json`)

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `id` | рядок (slug) | так | `a-z`, `0-9`, дефіси; збігається з назвою файлу; **не змінюється** при перейменуванні |
| `order` | ціле ≥ 1 | так | позиція в списку; маршрути йдуть саме в цьому порядку |
| `name` | рядок | так | назва (простий текст) |
| `lat`, `lng` | числа | так | координати, до 7 знаків |
| `desc` | рядок | ні | нотатки (простий текст) |
| `gmapsUrl` | рядок | ні | своє посилання Google Maps; порожнє — відкриється карта за координатами |
| `near` | рядок | ні | найближче селище/місто |
| `country` | рядок | ні | **країна англійською** (`Albania`). Сайт визначає її сам за координатами (Nominatim); скриптом — `fill-near` |
| `types` | масив id | ні | **типи місця** — id із `data/types.json`; одне місце може мати кілька типів (`["beach","nature"]`) |
| `aliases` | масив рядків | ні | інші id цієї картки (напр., id, який вона мала на сайті до першого імпорту). За ними сайт розпізнає картку й **не створює дубль** |
| `category` | рядок або `null` | ні | застаріле поле (замінене на `types`); лишилось для сумісності |
| `media` | масив | ні | `{type: "image"\|"video", file, thumb?, mime?, width?, height?, bytes}`; шляхи відносно `data/` |
| `updated` | `YYYY-MM-DD` | так | дата останньої зміни (виставляється скриптами) |

`data/index.json` — копія коротких полів усіх карток (`id, order, name, lat, lng, category, desc, near, country, types, gmapsUrl, thumb, photos, updated`).
Не редагуйте його вручну: він будується командою `npm run build-index` (разом з `data/users/index.json`).

### Типи місць (`data/types.json`)

```json
{ "version": 1, "types": [ { "id": "beach", "name": "Пляж", "icon": "🏖️" } ] }
```
`id` — стабільний ідентифікатор, на який посилаються картки; `name` і `icon` можна змінювати. Типи налаштовуються **на сайті**
(«⚙ → Типи місць» або «⚙ налаштувати типи» у формі картки): додати, перейменувати, змінити значок, видалити. Видалення прибирає тип з усіх карток.
Зміни потрапляють у репозиторій разом із файлом обміну. Вручну файл теж можна редагувати — `npm run validate` перевірить, що картки
посилаються лише на наявні типи.

### Особисті кабінети (`data/users/<id>.json`)

Паливо (`cons`, `price`, `cur`), збережені маршрути (`routes`), видалені маршрути (`deletedRoutes`) і налаштування екрана (`settings`:
положення плаваючої кнопки «＋» у частках екрана `fab {fx, fy}` та тема `light|dark`). `id` = транслітероване ім'я.
На сайті: «Особистий кабінет» → введіть ім'я → **Увійти**. Якщо таке ім'я є в `data/users/`, дані підтягуються з бази; якщо ні — створюється новий
користувач. **Вийти** — і можна зайти під іншим ім'ям або створити нове. Кнопка **Update** оновлює дані поточного користувача з бази разом із каталогом.
Дані кабінетів потрапляють у репозиторій разом із файлом обміну.
> Якщо репозиторій публічний, файли `data/users/` теж публічні. Не зберігайте там нічого, що не хочете показувати.

## Можливості сайту

- **Типи й фільтр.** Значок воронки над списком відкриває фільтр: країна, тип місця, час у дорозі (від–до, хв), відстань (від–до, км).
  Час і відстань — орієнтовні (по прямій ×1,3, 50 км/год), рахуються від моєї позиції (якщо ввімкнено «старт від мене»), інакше від першого вибраного місця, інакше від першого місця списку.
- **Країна** записується англійською автоматично за координатами при створенні картки (потрібен інтернет; без нього заповниться пізніше).
- **Маршрут.** Кнопки *routes / Route* пропонують Google Maps або Maps.me. Maps.me через посилання не приймає проміжні зупинки,
  тому маршрут будується від першої до останньої точки.
- **Тема.** «⚙ → Темна тема» перемикає світлий/темний вигляд; вибір запам'ятовується для користувача.
- **Плаваюча кнопка «＋»** (телефон) перетягується; її положення зберігається в налаштуваннях користувача.
- **Адаптивність.** Телефон (вузький екран) — одна колонка й кнопка «＋»; планшет і комп'ютер — список і панель з картою. На комп'ютері форма картки
  схована й відкривається кнопкою **＋** (або при редагуванні картки / кліку по карті).

## Офлайн і оновлення

- `sw.js` (service worker) зберігає сайт, дані, переглянуті фото й плитки карти. Онлайн сайт **завжди бере свіжу версію з GitHub**
  (кеш браузера обходиться), без інтернету — працює з останньої збереженої копії. Файл `sw.js` має лежати поруч з `index.html`.
- Додатково сайт сам перевіряє нову версію `index.html` при кожному відкритті й поверненні в додаток (кнопка **Update** теж) і перезавантажується.
  Якщо відкрита форма — лише повідомляє, що є оновлення.
- GitHub Pages віддає файли з кешем до ~10 хвилин, тож після `push` оновлення з'являється не миттєво.
- **Іконка на екрані «Додому» (iOS)** — окремий веб-режим із власним кешем: перший раз після такого оновлення закрийте додаток свайпом
  і відкрийте знову (або перевстановіть іконку зі Safari). Далі він оновлюватиметься сам.

## Як додати місце

Потрібен Node.js 18+ і `npm install` (один раз; для обробки фото потрібен пакет `sharp`).

**Скриптом**
```bash
npm run add-place                                  # інтерактивно
npm run add-place -- --name "Gjirokastër Castle" --coords "40.0758, 20.1389" \
    --desc "Фортеця" --country Albania --types history --photo ~/foto/1.jpg --photo ~/foto/2.jpg
npm run add-place -- --json нове.json              # з JSON (об'єкт або масив)
```
Координати можна вказати як `41.047, 19.496`, `40°43'16.5"N 19°28'11.5"E` або повний Plus Code `8FGXPFC9+GX`.
`--types a,b` — id типів із `data/types.json`. Позиція в списку: за замовчуванням нова картка стає **поряд із найближчою** (до 25 км), інакше в кінець;
`--position end|start|N|after:<id>` змінює це. Скрипт генерує `id`, перевіряє поля, стискає фото
до WebP (≤ 1600 px, ціль 200–400 КБ, + мініатюра) і оновлює `data/index.json`.

**Через Issue** — вкладка *Issues → New issue → Нове місце*: заповніть форму й прикріпіть фото.
Далі картку створюють командою вище (або вручну).

**Через Pull Request** — додайте `data/places/<id>.json`, фото в `data/photos/<id>/` і виконайте
`npm run build-index`; перевірка запуститься автоматично.

## Як оновити місце

```bash
npm run update-place -- <id> --desc "Новий опис" --near "Gjirokastër"
npm run update-place -- <id> --coords "40.0758, 20.1389" --url https://maps.app.goo.gl/...
npm run update-place -- <id> --country Albania --types history,nature     # порожнє значення очищає поле
npm run update-place -- <id> --add-photo нове.jpg --remove-photo 02
npm run update-place -- <id> --after <інший-id>      # змінити позицію (--first, --last, --at N)
```
Змінюються лише вказані поля; `updated` виставляється автоматично, `id` лишається тим самим.

Необов'язково: `npm run fill-near` заповнює `near` і `country` через Nominatim (не частіше 1 запиту/с); `-- --all` — для всіх карток.

## Перевірка

```bash
npm run build-index      # перебудувати data/index.json і data/users/index.json
npm run validate         # схема, унікальні id/порядок/аліаси, координати, типи, країни, користувачі, наявність фото, розміри, синхронність індексів
npm run check            # те й інше: індекси мають бути актуальними
npm run import-bundle -- файл.json   # імпорт файлу обміну (див. нижче)
```
GitHub Action `validate.yml` робить це на кожен push і pull request; якщо індекс застарів, перевірка падає з поясненням.
Посилання `gmapsUrl` перевіряються лише за форматом (мережею не ходимо).

## Запуск сайту локально

Сайт читає файли з `data/`, тому відкриття `index.html` просто з диска (`file://`) не працює — браузер блокує `fetch`.
Запустіть будь-який статичний сервер: `npx serve .` або `python3 -m http.server`.

## Обмеження GitHub

- Репозиторій і GitHub Pages — приблизно до 1 ГБ; окремий файл у репозиторії — до 100 МБ (скрипти й перевірка тримають 25 МБ).
- Через веб-інтерфейс GitHub файл можна завантажити до 25 МБ, а за один раз — до 100 файлів.
- Зміни на сайті з'являються через 1–2 хвилини після push; кеш Pages — до ~10 хв.

## Редагування на сайті та обмін одним файлом

**Що можна на сайті.** Кнопка ＋ додає місце; свайп вліво по картці — «Змінити» й «Видалити»;
порядок змінюється утриманням картки; фото до 5 МБ; до кожного місця можна додати один чи кілька типів.

**Куди це зберігається.** Тільки в браузері. Каталог із репозиторію — це основа: незмінені картки завжди беруться свіжими з нього,
а ваші нові/змінені/видалені картки та порядок накладаються зверху. **Update** не дублює картки: картку впізнають за `id`, за аліасом
(`aliases`) або за назвою поряд (до 3 км) і **збагачують** — порожні поля доповнюються, типи й нові фото додаються, ваші правки не втрачаються.
Скинути все до каталогу можна в «⚙ → Скинути зміни до каталогу».

**Файл обміну.** «⚙ → Експорт: усе одним файлом» створює `mymaps-YYYY-MM-DD.json` (версія 3). Він містить: усі місця (з країною, типами, аліасами),
**власні** фото повністю, а фото, що вже лежать у каталозі, — лише посиланням (`ref`), тому файл тепер легкий (десятки КБ замість десятків МБ),
список видалених карток, **довідник типів** і **кабінети користувачів**. Якщо файл виходить за 24 МБ, він ділиться на частини (`…-1.json`, `…-2.json`).
«⚙ → Імпорт із файлу…» читає такі файли (можна кілька відразу) і питає: **Об'єднати** чи **Замінити все**.

### Як вивантажити файл обміну в репозиторій

**Спосіб 1 — без програм, через сайт GitHub (рекомендовано; потрібне налаштування вище).**
1. Відкрийте репозиторій на github.com → тека `inbox/` → **Add file → Upload files**.
2. Перетягніть файл(и) `mymaps-….json` і натисніть **Commit changes**.
3. GitHub Action «Імпорт файлів обміну з inbox/» запуститься сам (вкладка **Actions**): по черзі (за назвами, частини `-1`, `-2`… у правильному порядку)
   імпортує файли в `data/`, стисне нові фото в WebP, оновить типи й кабінети, перебудує індекси, перевірить каталог, закомітить результат і видалить файли з `inbox/`.
4. Через 1–2 хвилини GitHub Pages покаже оновлений каталог; на сайті натисніть **Update** (або просто відкрийте сайт).

**Спосіб 2 — локально.** `npm install`, потім `npm run import-bundle -- шлях/до/mymaps.json`, `npm run validate`, `git add -A && git commit && git push`.
Прапори: `--dry` (лише показати, що зміниться), `--mirror` (видалити з каталогу все, чого немає у файлі).

**Правила імпорту.**
- Картки зіставляються за `id`, за старим `id` (`d0…d24` — через `migration/slugs.json`), за `aliases`, а далі за назвою поряд (до 100 м). Нові отримують читабельний slug із назви,
  а id із сайту (`pmv…`) записується в `aliases` — тому повторний імпорт **ніколи не дублює** картки, а лише збагачує їх.
- Фото, байти яких не змінились, лишаються без повторного стиснення; нові стискаються до WebP; `ref` вказує на вже наявне фото. Картки зі списку `deleted` видаляються.
- Порядок: картки з полем `order` стають на ці місця, а ті, яких у файлі немає, лишаються на своїх. Тому частини експорту можна імпортувати в будь-якій послідовності.
- **Захист від «відкату»:** файл, експортований **раніше** за дату останньої зміни картки (`updated`), лише збагачує її (заповнює порожнє, додає фото й типи) і нічого не перезаписує й не видаляє.
- Типи з файлу додаються в `data/types.json` (однакові назви зливаються); кабінети — у `data/users/<id>.json` (маршрути об'єднуються, новіша версія перемагає).
- Повторний імпорт того самого файлу нічого не змінює.

**Обережно:** файл, експортований після видалення місць, видалить ці картки й з репозиторію.

## Якщо щось не так

| Симптом | Причина й рішення |
|---|---|
| Файл у `inbox/` лежить і не обробляється | Немає `.github/workflows/import-inbox.yml` у репозиторії або вимкнені права запису. Див. «Одноразове налаштування GitHub» |
| Action завершується помилкою `npm ci` | У репозиторії немає `package-lock.json` або `package.json` — завантажте їх із цього архіву |
| На іконці «Додому» стара версія | Закрийте додаток свайпом і відкрийте знову; почекайте ~10 хв після push (кеш Pages) |
| Maps.me питає «Відкрити?» | Це системне підтвердження iOS для посилань на інші програми, вимкнути його з боку сайту неможливо |
