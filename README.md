# SanMarynaGO — каталог місць

Статичний сайт для GitHub Pages: список місць, карта, фільтр, вибір місць для маршруту (час і відстань), перегляд фото.
Дані лежать у репозиторії як файли, а не вшиті в `index.html`. На самому сайті місця можна додавати, змінювати, видаляти й упорядковувати,
але ці зміни зберігаються **лише в браузері** і в репозиторій не потрапляють, поки ви не вивантажите файл обміну (розділ нижче).

## Структура

```
index.html                 сайт: читає каталог із data/, ваші зміни зберігає лише у браузері (IndexedDB / localStorage)
sw.js                      service worker: офлайн-режим (див. «Офлайн і оновлення»). Має лежати поруч з index.html
apple-touch-icon.png       іконка для «Додому» на iPhone
data/
  index.json               легкий список для карти й списку (будується скриптом)
  types.json               довідник типів місць: пляж, ресторан, екстрім, винарня… (id, назва, значок)
  places/<id>.json         одна картка = один файл (єдине джерело правди)
  photos/<id>/NN.webp      фото до 1600 px (WebP), NN_thumb.webp — мініатюра; NN.mp4 — відео без перекодування
  users/<id>.json          особисті кабінети: паливо, збережені маршрути, налаштування екрана (з'являється після першого експорту)
  users/index.json         список користувачів (будується скриптом)
schema/                    JSON Schema: place.schema.json, types.schema.json, user.schema.json
scripts/                   add-place, update-place, import-bundle, build-index, validate, fill-near, migrate
inbox/                     сюди завантажують файл обміну — Action сам додасть його в каталог
migration/                 вихідна копія даних до переходу на каталог (places.original.json.gz) і таблиця id (slugs.json)
.github/workflows/validate.yml         перевірка на кожен push і pull request
.github/workflows/import-inbox.yml     імпорт файлів обміну з inbox/ (комітить результат сам)
.github/ISSUE_TEMPLATE/new-place.yml   форма «Нове місце»
github-setup/              запасні копії файлів `.github/` (див. нижче — це важливо)
```

## ⚠️ Одноразове налаштування GitHub (без нього файли з `inbox/` не імпортуються)

1. **Папка `.github/` має бути в репозиторії.** Папки з крапкою на початку часто **не потрапляють** при завантаженні через веб-інтерфейс
   (їх ховає Finder/Провідник і пропускає «перетягування»). Перевірте на github.com: чи є `.github/workflows/import-inbox.yml`.
   Якщо ні — створіть файли вручну за інструкцією в `github-setup/README.md` (це 3 копіювання тексту).
2. **Settings → Actions → General → Workflow permissions → Read and write permissions → Save.** Інакше робот не зможе закомітити результат.
3. **Settings → Pages**: Source — Deploy from a branch → `main` / `(root)`.
4. Перевірка: вкладка **Actions** має показувати «Імпорт файлів обміну з inbox/» і «Перевірка каталогу». Імпорт можна запустити й вручну:
   Actions → «Імпорт файлів обміну…» → **Run workflow**.

## Поля картки (`data/places/<id>.json`)

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `id` | рядок (slug) | так | `a-z`, `0-9`, дефіси; збігається з назвою файлу; **не змінюється** при перейменуванні |
| `order` | ціле ≥ 1 | так | позиція в списку; маршрути йдуть саме в цьому порядку |
| `name` | рядок | так | назва (простий текст) |
| `lat`, `lng` | числа | так | координати, до 7 знаків |
| `desc` | рядок | ні | нотатки (простий текст) |
| `gmapsUrl` | рядок | ні | своє посилання Google Maps; порожнє — відкриється карта за координатами |
| `near` | рядок | ні | найближче селище/місто |
| `country` | рядок | ні | **країна англійською** (`Albania`). Сайт визначає її сам за координатами (Nominatim); скриптом — `fill-near` |
| `types` | масив id | ні | **типи місця** — id із `data/types.json`; одне місце може мати кілька типів (`["beach","nature"]`) |
| `aliases` | масив рядків | ні | інші id цієї картки (напр., id, який вона мала на сайті до першого імпорту). За ними сайт розпізнає картку й **не створює дубль** |
| `category` | рядок або `null` | ні | застаріле поле (замінене на `types`); лишилось для сумісності |
| `media` | масив | ні | `{type: "image"\|"video", file, thumb?, mime?, width?, height?, bytes}`; шляхи відносно `data/` |
| `updated` | `YYYY-MM-DD` | так | дата останньої зміни (виставляється скриптами) |

`data/index.json` — копія коротких полів усіх карток (`id, order, name, lat, lng, category, desc, near, country, types, gmapsUrl, thumb, photos, updated`).
Не редагуйте його вручну: він будується командою `npm run build-index` (разом з `data/users/index.json`).

### Типи місць (`data/types.json`)

```json
{ "version": 1, "types": [ { "id": "beach", "name": "Пляж", "icon": "🏖️" } ] }
```
`id` — стабільний ідентифікатор, на який посилаються картки; `name` і `icon` можна змінювати. Типи налаштовуються **на сайті**
(«⚙ → Типи місць»): додати, перейменувати, змінити значок, видалити. Видалення прибирає тип з усіх карток.
Зміни потрапляють у репозиторій разом із файлом обміну. Вручну файл теж можна редагувати — `npm run validate` перевірить, що картки
посилаються лише на наявні типи.

### Особисті кабінети (`data/users/<id>.json`)

Паливо (`cons`, `price`, `cur`), збережені маршрути (`routes`), видалені маршрути (`deletedRoutes`) і налаштування екрана (`settings`:
положення плаваючої кнопки «＋» у частках екрана `fab {fx, fy}` та тема `light|dark`). `id` = транслітероване ім'я.
На сайті: «Особистий кабінет» → введіть ім'я → **Увійти**. Кабінети зберігаються **лише в браузері** й **не підтягуються з GitHub**: якщо ім'я вже є
в цьому браузері — відкриються його дані, якщо ні — буде створено нового користувача. **Вийти** — і можна зайти під іншим ім'ям або створити нове.
У репозиторій кабінети потрапляють разом із файлом обміну (⚙ → Експорт) як резервна копія; сайт її назад не читає (лише «Імпорт із файлу» у ⚙ зливає кабінети з файлу).
> Якщо репозиторій публічний, файли `data/users/` теж публічні. Не зберігайте там нічого, що не хочете показувати.

## Можливості сайту

- **Типи й фільтр.** Значок воронки над списком відкриває фільтр: країна, тип місця, час у дорозі (від–до, хв), відстань (від–до, км).
  Час і відстань — орієнтовні (по прямій ×1,3, 50 км/год) і рахуються від вашої позиції (GPS); поки її немає — від першого місця списку.
  Вибір карток на фільтр не впливає. Головний чекбокс над списком вибирає всі **видимі** картки, а повторне натискання знімає **всі** (і приховані фільтром теж).
- **Сортування.** Вікно «🔎 Фільтр і сортування» (воронка на головному екрані **і на карті**) має два режими.
  **«Мій порядок»** (типовий) — список вибудовується **зверху вниз від найближчого місця до найдальшого** (відстань від вашої позиції: GPS, а якщо його ще немає — остання відома).
  Це робиться **при кожному відкритті сайту** (за останньою відомою позицією, а коли GPS дасть перший справжній сигнал — ще раз, якщо ви далеко від збереженої позиції; не під час дій у формі, на карті, в меню).
  Протягом візиту порядок ваш: утримайте картку й перетягніть. Повторне натискання «Мій порядок» перебудовує список за відстанню заново (це стирає ваш ручний порядок); при наступному відкритті сайту він теж вибудовується заново. Перетягуючи картку біля краю екрана, список прокручується **вдвічі повільніше**, ніж раніше.
  **«За групою й відстанню»** — за типом місця (порядок груп — як у списку типів, без типу — в кінці), а в межах групи від найближчого; перевпорядковується автоматично при запуску,
  після змін у картках і коли ви пересунулись більше ніж на 1 км (лише коли ви нічого не робите). Раніше збережений режим «За групою…» при першому запуску цієї версії один раз змінюється на «Мій порядок».
  Номер картки (поруч із квадратиком) — її місце в списку; маршрут будується в порядку списку.
  **Порядок у файлі обміну:** автоматичне сортування за відстанню **не вважається зміною даних** і в експорт не потрапляє. Повний список порядку (`order`) експортується лише якщо ви перетягнули картки
  **і не відкривали сайт заново** (при відкритті сайту «Мій порядок» вибудовується за відстанню й прапорець скидається); після експорту прапорець теж скидається.
- **Рядок під назвою картки.** `📍 селище · (колесо) відстань · ⏱ час у дорозі · ⛰ висота`. Відстань (по прямій) — від вашого поточного місця, оновлюється, коли ви пересунулись більше ніж на 30 м.
  **Час у дорозі** машиною від вашого місця рахується одним запитом до OSRM (`routing.openstreetmap.de`, запасний — `router.project-osrm.org`) для всіх карток відразу;
  оновлюється, коли ви пересунулись більш ніж на 1 км або через 10 хв; без інтернету показується груба оцінка зі значком `≈` (по прямій × 1,4 при 50 км/год).
  Висота над рівнем моря береться з Open-Meteo один раз для кожного місця (потрібен інтернет; результат зберігається в браузері й оновлюється, якщо змінено координати);
  висота **менше 100 м не показується**. Значок і число ніколи не розриваються між рядками: якщо не вміщається, на новий рядок переходить усе разом.
  Сірий ланцюжок після назви означає, що до картки прив'язано своє посилання Google Maps. Значок колеса (литий диск) позначає відстань усюди: у картках, у вікні вартості (кнопка €),
  у підсумку маршруту на карті й у вікні сортування.
- **Відгуки замість нотаток.** Під назвою картки — **історія відгуків**: хто додав, коли, і його текст (показано два останніх, решта — «▸ N earlier reviews»). Кнопка **＋ Review** додає свій відгук;
  **✎ / ✕** є лише біля відгуків, які можна змінювати: **свої — будь-який користувач, а Alex — будь-які**. Ім'я автора береться з імені в особистому кабінеті (без імені — «Guest»).
  У форму нового місця поле «Review» додає перший відгук; для наявного місця відгуки редагуються на картці. Зберігаються відгуки в полі `desc` звичайним текстом, тож репозиторій і скрипти нічого не потребують:
  `[Alex · 2026-11-19 14:05]` у рядку-заголовку, далі текст, між відгуками порожній рядок. Стара звичайна нотатка читається як один відгук від Alex (без дати).
- **Типи для медицини.** Тип з іконкою **✚** малюється **червоним хрестом**. Типи, назва яких схожа на медицину (hospital, pharmacy, clinic, лікарня, аптека…) і які ще без іконки, отримують ✚ автоматично;
  якщо медичних типів немає зовсім, один раз додаються **Hospital**, **Pharmacy**, **Clinic** (їх можна перейменувати чи видалити в «Типи місць»; нові типи потрапляють у наступний експорт).
- **Пошук.** У пошуку на головному екрані й на карті достатньо **2 символів**: шукає за назвою, містом, описом і… **номером картки** (`12`, `012` або `#12`). На карті в полі після першого символа
  з'являється кнопка **✕** «стерти все».
- **Прокрутка й фото в списку.** На телефонах прокрутка рідна: інерцію дає браузер, а картка «прилипає» рівно під верхньою смугою завдяки CSS `scroll-snap` (власні покадрові
  анімації `scrollTop` — швидкий кидок і дотягування — там вимкнено, бо після оновлення iOS через них зникали фото й дотягування працювало некоректно). Для миші (комп'ютер) власне
  дотягування лишилось. Щоб повернути старі анімації на телефонах, у `index.html` змініть визначення `NATIVE_SNAP` на `false`. Для власних фото (до 5 МБ) у списку показується
  мініатюра (≈360 px), яку сайт створює сам при додаванні й дозавантажує фоном для старих фото; повне фото відкривається в перегляді, а у файл обміну мініатюри не потрапляють.
- **Країна** записується англійською автоматично за координатами при створенні картки (потрібен інтернет; без нього заповниться пізніше).
- **Маршрут.** Кнопка «Маршрут» одразу відкриває Google Maps (дуже довгий маршрут — частину 1, решту відкривають кнопки «Ч2», «Ч3»…). Якщо вибрано **одну** точку,
  маршрут будується від вашого поточного місця до неї (на карті й у Google Maps). Вікно вибору програми (Google Maps / Maps.me) збережено в коді, але вимкнено:
  щоб повернути, у `index.html` змініть `let ROUTE_CHOOSER_ENABLED = false` на `true` (і приберіть правило `#navMapsmeBtn { display: none !important; }`).
  Maps.me через посилання не приймає проміжні зупинки, тому йому передається маршрут із **двох точок: від вашого поточного місця до найближчої точки маршруту**
  (потрібен доступ до GPS; без нього маршрут не будується — запасного старту від першої точки немає). Якщо GPS ще не відповів, з'явиться кнопка «Відкрити в Maps.me»:
  iOS дозволяє перехід в іншу програму лише з натискання користувача.
- **Повернення з карт.** На iPhone в режимі «На екран Додому» зовнішні посилання відкриваються звичайною навігацією, а не `window.open`: так не лишається порожньої
  вкладки вбудованого браузера («Search or enter website name»). Після повернення з Google Maps додаток закриває накладку карти й показує головний екран.
- **GPS і висота.** Біля напису «SanMarynaGO» (у шапці й на карті) стоїть овал із висотою над рівнем моря від GPS. **Натискання на нього повторює втрачений GPS** («Retrying GPS…»).
  Дозвіл на геолокацію сайт просить **лише при першому вході**; далі, якщо браузер пам'ятає дозвіл, GPS підключається сам. Якщо браузер дозвіл «забув» (на iPhone в режимі «Додому» це буває),
  при відкритті запит не повторюється — GPS стартує, коли ви відкриєте карту чи спідометр або натиснете на висоту.
- **Карта.** Відкривається **на вашому місці по центру екрана** в масштабі ≈ 11 (видно всю затоку з сусідніми картками) і йде за вами, поки ви не потягнете карту; зелена кнопка «ви тут» повертає слідкування.
  Якщо на карті вже вибрані точки маршруту чи відкритий трек, лишається огляд усього маршруту. Під час запису треку масштаб ближчий (16,5), щоб було видно дороги.
  **Тап по порожній карті** закриває відкриті записані треки; кнопка **⟲** («скинути все») знімає вибрані точки **і** закриває відкриті треки (під час запису треки не чіпає).
  Пошук на карті — вдвічі вужчий і ліворуч; під кнопкою скидання — **воронка (фільтр)** і **стрілки (сортування)**: це те саме вікно, що й на головному екрані, а фільтр відразу діє й на маркери карти
  (вибрані точки лишаються завжди). Назви місць на темній карті — темний текст на світлій плашці. Коли розгорнуто список типів карти, кнопки **Rec** і **Trips** опускаються під нього.
- **Запис треку.** Лінія запису — **зелена**. Вікно статистики піднімається над нижнім рядком із кілометрами й часом маршруту, щоб його не перекривати.
- **Тріпи.** Кнопка **Trips** на карті показує записані треки **і всі збережені маршрути з особистого кабінету** («Open» додає точки маршруту до вже вибраних, «✕» видаляє). Можна відкрити
  **кілька треків одночасно**; відкритий трек зі списку зникає (і повертається, коли його закрито). Вікно розрахунку вартості (кнопка €) рахує **усі відкриті треки разом із вибраними точками**;
  на головному екрані кнопка € з'являється лише для вибраних точок (не для треків), на карті — і для треків.
- **Спідометр.** Квадратний значок над списком (як кнопка «зберегти»): білий круглий циферблат, стрілка показує швидкість, у центрі — індикатор GPS
  (жовтий — очікування, зелений — активний, червоний — немає сигналу). Натискання відкриває повноекранний GPS-спідометр; швидкість береться з того самого
  GPS-потоку, що й карта. Колір фону залежить від швидкості: до 50 км/год — темний, 50–70 — приглушений зелений, 70–90 — помаранчевий,
  90–120 — рожевий, від 120 — бордовий. Закривається свайпом угору чи вниз (або кнопкою ✕).
  Поки спідометр відкритий, екран телефона **не гасне** (Screen Wake Lock; на iPhone додатково працює запасний варіант — беззвучне відео в циклі). Після закриття спідометра екран знову гасне як звичайно.
- **Шапка й смуга над списком.** На телефоні шапка в один рядок: кабінет, назва, спідометр, карта, маршрут, «повернутися на старт», налаштування.
  Карта, маршрут і «повернутися на старт» — квадратні кнопки-піктограми 38×38 у стилі кнопки «зберегти» (без тексту); підказка з'являється при наведенні миші
  або довгому натисканні (дію кнопки при цьому не виконано). Увімкнений «повернутися на старт» має темніший фон із білим кільцем.
  Друга смуга: вибір усіх, цифри розрахунку (завжди в один рядок — шрифт зменшується), «зберегти» і фільтр (праворуч під шестірнею).
  На комп'ютері «маршрут» і «повернутися на старт» — такі самі квадратні кнопки в панелі праворуч.
- **Maps.me тимчасово приховано** у вікні вибору програми для маршруту (правило `#navMapsmeBtn { display: none !important; }` в `index.html`; щоб повернути кнопку — видаліть цей рядок).
- **Офлайн.** Коли немає інтернету, на аватарі профілю з'являється значок перекресленого Wi-Fi.
- **Вибір карток.** Вибрана картка показує серце-рамку замість квадрата.
- **Тема.** «⚙ → Темна тема» перемикає світлий/темний вигляд; вибір запам'ятовується для користувача.
- **Плаваюча кнопка «＋»** (телефон) перетягується; її положення зберігається в налаштуваннях користувача.
- **Адаптивність.** Телефон (вузький екран) — одна колонка й кнопка «＋»; планшет і комп'ютер — список і панель з картою. На комп'ютері форма картки
  схована й відкривається кнопкою **＋** (або при редагуванні картки / кліку по карті).

## Офлайн і оновлення

- `sw.js` (service worker) зберігає програму, дані, переглянуті фото й плитки карти. **Програма (`index.html`) оновлюється лише кнопкою «Update Software»**:
  при відкритті сайту береться збережена копія, а нова версія тільки перевіряється (червоне число на шестірні й підсвічена кнопка в налаштуваннях). Дані каталогу, фото й файли сайту
  онлайн беруться свіжими, без інтернету — зі збереженої копії; плитки карти й скрипти Leaflet — зі збереженої копії, що оновлюється у фоні. Файл `sw.js` має лежати поруч з `index.html`
  і **заливається разом з ним** (без нового `sw.js` сайт, як і раніше, бере свіжий `index.html` при кожному відкритті).
- Поки йде **Update** або **Експорт**, показується зелена змійка-індикатор і грає звук очікування (вимикається разом зі звуком у «⚙»). Після Update картки, які репозиторій уже має, перестають бути «зміненими»
  (локальні копії фото замінюються фото з репозиторію; у підсумку: «already on GitHub N»).
- Сайт сам **лише перевіряє**, чи є нова версія `index.html` (при відкритті й у налаштуваннях), і показує це червоним числом на шестірні. Нічого не перезавантажується,
  поки ви не натиснете **Update Software**: тоді service worker завантажує нову програму, зберігає її, і сторінка перезапускається вже з нею.
- GitHub Pages віддає файли з кешем до ~10 хвилин, тож після `push` оновлення з'являється не миттєво.
- **Іконка на екрані «Додому» (iOS)** — окремий веб-режим із власним кешем: перший раз після такого оновлення закрийте додаток свайпом
  і відкрийте знову (або перевстановіть іконку зі Safari). Далі він оновлюватиметься сам.

## Як додати місце

Потрібен Node.js 18+ і `npm install` (один раз; для обробки фото потрібен пакет `sharp`).

**Скриптом**
```bash
npm run add-place                                  # інтерактивно
npm run add-place -- --name "Gjirokastër Castle" --coords "40.0758, 20.1389" \
    --desc "Фортеця" --country Albania --types history --photo ~/foto/1.jpg --photo ~/foto/2.jpg
npm run add-place -- --json нове.json              # з JSON (об'єкт або масив)
```
Координати можна вказати як `41.047, 19.496`, `40°43'16.5"N 19°28'11.5"E` або повний Plus Code `8FGXPFC9+GX`.
`--types a,b` — id типів із `data/types.json`. Позиція в списку: за замовчуванням нова картка стає **поряд із найближчою** (до 25 км), інакше в кінець;
`--position end|start|N|after:<id>` змінює це. Скрипт генерує `id`, перевіряє поля, стискає фото
до WebP (≤ 1600 px, ціль 200–400 КБ, + мініатюра) і оновлює `data/index.json`.

**Через Issue** — вкладка *Issues → New issue → Нове місце*: заповніть форму й прикріпіть фото.
Далі картку створюють командою вище (або вручну).

**Через Pull Request** — додайте `data/places/<id>.json`, фото в `data/photos/<id>/` і виконайте
`npm run build-index`; перевірка запуститься автоматично.

## Як оновити місце

```bash
npm run update-place -- <id> --desc "Новий опис" --near "Gjirokastër"
npm run update-place -- <id> --coords "40.0758, 20.1389" --url https://maps.app.goo.gl/...
npm run update-place -- <id> --country Albania --types history,nature     # порожнє значення очищає поле
npm run update-place -- <id> --add-photo нове.jpg --remove-photo 02
npm run update-place -- <id> --after <інший-id>      # змінити позицію (--first, --last, --at N)
```
Змінюються лише вказані поля; `updated` виставляється автоматично, `id` лишається тим самим.

Необов'язково: `npm run fill-near` заповнює `near` і `country` через Nominatim (не частіше 1 запиту/с); `-- --all` — для всіх карток.

## Перевірка

```bash
npm run build-index      # перебудувати data/index.json і data/users/index.json
npm run validate         # схема, унікальні id/порядок/аліаси, координати, типи, країни, користувачі, наявність фото, розміри, синхронність індексів
npm run check            # те й інше: індекси мають бути актуальними
npm run import-bundle -- файл.json   # імпорт файлу обміну (див. нижче)
```
GitHub Action `validate.yml` робить це на кожен push і pull request; якщо індекс застарів, перевірка падає з поясненням.
Посилання `gmapsUrl` перевіряються лише за форматом (мережею не ходимо).

## Запуск сайту локально

Сайт читає файли з `data/`, тому відкриття `index.html` просто з диска (`file://`) не працює — браузер блокує `fetch`.
Запустіть будь-який статичний сервер: `npx serve .` або `python3 -m http.server`.

## Обмеження GitHub

- Репозиторій і GitHub Pages — приблизно до 1 ГБ; окремий файл у репозиторії — до 100 МБ (скрипти й перевірка тримають 25 МБ).
- Через веб-інтерфейс GitHub файл можна завантажити до 25 МБ, а за один раз — до 100 файлів.
- Зміни на сайті з'являються через 1–2 хвилини після push; кеш Pages — до ~10 хв.

## Редагування на сайті та обмін одним файлом

**Що можна на сайті.** Кнопка ＋ додає місце; свайп вліво по картці — «Змінити» й «Видалити»;
порядок змінюється утриманням картки; фото до 5 МБ; до кожного місця можна додати один чи кілька типів.

**Куди це зберігається.** Тільки в браузері. Каталог із репозиторію — це основа: незмінені картки завжди беруться свіжими з нього,
а ваші нові/змінені/видалені картки та порядок накладаються зверху. **Update** не дублює картки: картку впізнають за `id`, за аліасом
(`aliases`) або за назвою поряд (до 3 км) і **збагачують** — порожні поля доповнюються, типи й нові фото додаються, ваші правки не втрачаються.
Скинути все до каталогу можна в «⚙ → Скинути зміни до каталогу».

**Файл обміну.** «⚙ → Експорт: усе одним файлом» створює `mymaps-YYYY-MM-DD.json` (версія 3). Він містить: усі місця (з країною, типами, аліасами),
**власні** фото повністю, а фото, що вже лежать у каталозі, — лише посиланням (`ref`), тому файл тепер легкий (десятки КБ замість десятків МБ),
список видалених карток, **довідник типів** і **кабінети користувачів**. Файл **не більший за 20 МБ**; якщо даних більше, експорт ділиться на частини (`…-1.json`, `…-2.json`) — саме в такому вигляді їх приймає папка `inbox/`.
**Експорт вивантажує лише те, що відрізняється від репозиторію.** Натискання кнопки порівнює дані браузера з каталогом на GitHub (назва, координати, опис, посилання, типи, фото…) і кладе у файли
лише нові чи змінені картки. Службові додатки до посилань Google Maps (`?g_st=…`) різницею не вважаються. Фото, які вже є в репозиторії (в тому числі перекодовані ним), не вивантажуються повторно;
для карток, які репозиторій уже має, замість локальних копій береться його список фото. Якщо фото картки разом **не вміщуються в 20 МБ**, у цей файл беруться ті, що вміщуються, а решта — при
наступному експорті після завантаження цих файлів у репозиторій (програма порівняє з GitHub ще раз). Одне фото більше за 20 МБ пропускається з порадою його зменшити.
Поки формується експорт, показується зелена змія й грає звук сонара; після того як файли передано (вікно «Поділитися» закрите), усі вікна згортаються й відкриваються налаштування.
Якщо щось усе-таки вивантажується, програма показує вікно з **причиною** («Beach Dhermi — photos») і для карток, що відрізняються лише фото, пропонує: **OK** — «ці фото вже на GitHub» (беруться фото з репозиторію,
картка більше не експортується), **Скасувати** — лишити локальні. Профілі (кабінети) вивантажуються завжди — їх немає з чим порівняти.
«⚙ → Імпорт із файлу…» читає такі файли (можна кілька відразу) і питає: **Об'єднати** чи **Замінити все**.

### Як вивантажити файл обміну в репозиторій

**Спосіб 1 — без програм, через сайт GitHub (рекомендовано; потрібне налаштування вище).**
1. Відкрийте репозиторій на github.com → тека `inbox/` → **Add file → Upload files**.
2. Перетягніть файл(и) `mymaps-….json` і натисніть **Commit changes**.
3. GitHub Action «Імпорт файлів обміну з inbox/» запуститься сам (вкладка **Actions**): по черзі (за назвами, частини `-1`, `-2`… у правильному порядку)
   імпортує файли в `data/`, стисне нові фото в WebP, оновить типи й кабінети, перебудує індекси, перевірить каталог, закомітить результат і видалить файли з `inbox/`.
4. Через 1–2 хвилини GitHub Pages покаже оновлений каталог; на сайті натисніть **Update** (або просто відкрийте сайт).

**Спосіб 2 — локально.** `npm install`, потім `npm run import-bundle -- шлях/до/mymaps.json`, `npm run validate`, `git add -A && git commit && git push`.
Прапори: `--dry` (лише показати, що зміниться), `--mirror` (видалити з каталогу все, чого немає у файлі).

**Правила імпорту.**
- Картки зіставляються за `id`, за старим `id` (`d0…d24` — через `migration/slugs.json`), за `aliases`, а далі за назвою поряд (до 100 м). Нові отримують читабельний slug із назви,
  а id із сайту (`pmv…`) записується в `aliases` — тому повторний імпорт **ніколи не дублює** картки, а лише збагачує їх.
- Фото, байти яких не змінились, лишаються без повторного стиснення; нові стискаються до WebP; `ref` вказує на вже наявне фото. Картки зі списку `deleted` видаляються.
- Порядок: картки з полем `order` стають на ці місця, а ті, яких у файлі немає, лишаються на своїх. Тому частини експорту можна імпортувати в будь-якій послідовності.
- **Захист від «відкату»:** файл, експортований **раніше** за дату останньої зміни картки (`updated`), лише збагачує її (заповнює порожнє, додає фото й типи) і нічого не перезаписує й не видаляє.
- Типи з файлу додаються в `data/types.json` (однакові назви зливаються); кабінети — у `data/users/<id>.json` (маршрути об'єднуються, новіша версія перемагає).
- Повторний імпорт того самого файлу нічого не змінює.

**Обережно:** файл, експортований після видалення місць, видалить ці картки й з репозиторію.

## Якщо щось не так

| Симптом | Причина й рішення |
|---|---|
| Файл у `inbox/` лежить і не обробляється | Немає `.github/workflows/import-inbox.yml` у репозиторії або вимкнені права запису. Див. «Одноразове налаштування GitHub» |
| Action завершується помилкою `npm ci` | У репозиторії немає `package-lock.json` або `package.json` — завантажте їх із цього архіву |
| На іконці «Додому» стара версія | Закрийте додаток свайпом і відкрийте знову; почекайте ~10 хв після push (кеш Pages) |
| Після експорту й завантаження файлів у `inbox/` картки знову вивантажуються | Натисніть **Update**, потім експорт. Якщо картка лишилась, вікно після експорту назве поле, що відрізняється; для «photos» натисніть OK (фото вже на GitHub) |
| Додаток знову просить доступ до геолокації | Дозвіл зберігає браузер, не сайт. iPhone: Налаштування → Safari → Геопозиція → для сайту «Дозволити» (в режимі «Додому» запит може повторюватись) |
| Maps.me питає «Відкрити?» | Це системне підтвердження iOS для посилань на інші програми, вимкнути його з боку сайту неможливо |
| Маршрут у Maps.me не будується | Maps.me потрібна завантажена офлайн-карта регіону; проміжні зупинки він не приймає |

Старий `index.html` з вбудованими даними лишається в історії git. Вихідні дані на момент переходу на каталог збережено в
`migration/source/places.original.json.gz`; `npm run migrate` порівнює каталог з ними (повторний запуск нічого не дублює й не перезаписує наявні картки; `--force` перезаписує).
