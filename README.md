# MyMaps — каталог місць

Статичний сайт для GitHub Pages: список місць, карта, вибір місць для маршруту (час і відстань), перегляд фото.
Дані лежать у репозиторії як файли, а не вшиті в `index.html`. На самому сайті місця можна додавати, змінювати, видаляти й упорядковувати,
але ці зміни зберігаються **лише в браузері** і в репозиторій не потрапляють, поки ви не вивантажите файл обміну (розділ нижче).

## Структура

```
index.html                 сайт: читає каталог із data/, зміни зберігає лише у вашому браузері (IndexedDB)
apple-touch-icon.png       іконка для «Додому» на iPhone
data/
  index.json               легкий список для карти й списку (будується скриптом)
  places/<id>.json         одна картка = один файл (єдине джерело правди)
  photos/<id>/NN.webp      фото до 1600 px (WebP), NN_thumb.webp — мініатюра; NN.mp4 — відео без перекодування
schema/place.schema.json   JSON Schema картки
scripts/                   add-place, update-place, import-bundle, build-index, validate, fill-near, migrate
inbox/                     сюди завантажують файл обміну — Action сам додасть його в каталог
migration/                 вихідна копія даних до переходу на каталог (places.original.json.gz) і таблиця id (slugs.json)
.github/workflows/validate.yml      перевірка на кожен push і pull request
.github/workflows/import-inbox.yml  імпорт файлу обміну з inbox/ (комітить результат сам)
.github/ISSUE_TEMPLATE/new-place.yml   форма «Нове місце»
```

## Поля картки (`data/places/<id>.json`)

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `id` | рядок (slug) | так | `a-z`, `0-9`, дефіси; збігається з назвою файлу; **не змінюється** при перейменуванні |
| `order` | ціле ≥ 1 | так | позиція в списку; маршрути йдуть саме в цьому порядку |
| `name` | рядок | так | назва (простий текст) |
| `lat`, `lng` | числа | так | координати, до 7 знаків |
| `desc` | рядок | ні | нотатки (простий текст) |
| `gmapsUrl` | рядок | ні | своє посилання Google Maps; порожнє — відкриється карта за координатами |
| `near` | рядок | ні | найближче селище/місто |
| `category` | рядок або `null` | ні | категорія (сайт поки не використовує) |
| `media` | масив | ні | `{type: "image"\|"video", file, thumb?, mime?, width?, height?, bytes}`; шляхи відносно `data/` |
| `updated` | `YYYY-MM-DD` | так | дата останньої зміни (виставляється скриптами) |

`data/index.json` — це копія коротких полів усіх карток (`id, order, name, lat, lng, category, desc, near, gmapsUrl, thumb, photos, updated`).
Не редагуйте його вручну: він будується командою `npm run build-index`.

## Як додати місце

Потрібен Node.js 18+ і `npm install` (один раз; для обробки фото потрібен пакет `sharp`).

**Скриптом**
```bash
npm run add-place                                  # інтерактивно
npm run add-place -- --name "Gjirokastër Castle" --coords "40.0758, 20.1389" \
    --desc "Фортеця" --photo ~/foto/1.jpg --photo ~/foto/2.jpg
npm run add-place -- --json нове.json              # з JSON (об'єкт або масив)
```
Координати можна вказати як `41.047, 19.496`, `40°43'16.5"N 19°28'11.5"E` або повний Plus Code `8FGXPFC9+GX`.
Позиція в списку: за замовчуванням нова картка стає **поряд із найближчою** (до 25 км), інакше в кінець;
`--position end|start|N|after:<id>` змінює це. Скрипт генерує `id`, перевіряє поля, стискає фото
до WebP (≤ 1600 px, ціль 200–400 КБ, + мініатюра) і оновлює `data/index.json`.

**Через Issue** — вкладка *Issues → New issue → Нове місце*: заповніть форму й прикріпіть фото.
Далі картку створюють командою вище (або вручну).

**Через Pull Request** — додайте `data/places/<id>.json`, фото в `data/photos/<id>/` і виконайте
`npm run build-index`; перевірка запуститься автоматично.

## Як оновити місце

```bash
npm run update-place -- <id> --desc "Новий опис" --near "Gjirokastër"
npm run update-place -- <id> --coords "40.0758, 20.1389" --url https://maps.app.goo.gl/...
npm run update-place -- <id> --add-photo нове.jpg --remove-photo 02
npm run update-place -- <id> --after <інший-id>      # змінити позицію (--first, --last, --at N)
npm run update-place -- <id> --desc ""               # порожнє значення очищає поле
```
Змінюються лише вказані поля; `updated` виставляється автоматично, `id` лишається тим самим.

Необов'язково: `npm run fill-near` заповнює `near` через Nominatim (не частіше 1 запиту/с).

## Перевірка

```bash
npm run build-index      # перебудувати data/index.json
npm run validate         # схема, унікальні id/порядок, координати, наявність фото, розміри, синхронність index.json
npm run check            # те й інше: index.json має бути актуальним
npm run import-bundle -- файл.json   # імпорт файлу обміну (див. нижче)
```
GitHub Action `validate.yml` робить це на кожен push і pull request; якщо `index.json` застарів, перевірка падає з поясненням.
Посилання `gmapsUrl` перевіряються лише за форматом (мережею не ходимо).

## Запуск сайту локально

Сайт читає файли з `data/`, тому відкриття `index.html` просто з диска (`file://`) не працює — браузер блокує `fetch`.
Запустіть будь-який статичний сервер: `npx serve .` або `python3 -m http.server`.
У браузері зберігаються ваші локальні зміни, вибір місць (серця) і перемикач «Повернутися на старт».

## Обмеження GitHub

- Репозиторій і GitHub Pages — приблизно до 1 ГБ; окремий файл у репозиторії — до 100 МБ (скрипти й перевірка тримають 25 МБ).
- Через веб-інтерфейс GitHub файл можна завантажити до 25 МБ.
- Зміни на сайті з'являються через 1–2 хвилини після push; браузер може показувати кеш — оновіть сторінку.

## Редагування на сайті та обмін одним файлом

**Що можна на сайті.** Кнопка ＋ (телефон) або форма справа (комп'ютер) додає місце; свайп вліво по картці — «Змінити» й «Видалити»;
порядок змінюється утриманням картки; фото до 5 МБ. Нове місце ставиться поряд зі схожим за територією.

**Куди це зберігається.** Тільки в браузері (IndexedDB). Каталог із репозиторію — це основа: незмінені картки завжди беруться
свіжими з нього, а ваші нові/змінені/видалені картки та порядок накладаються зверху. Скинути все до каталогу можна
в «⚙ → Скинути зміни до каталогу». У «⚙» видно, скільки локальних змін є.

**Файл обміну.** «⚙ → Експорт: усе одним файлом» створює `mymaps-YYYY-MM-DD.json` (десь 8–10 МБ): усі місця, усі фото всередині
(base64) і список видалених карток каталогу. «⚙ → Імпорт із файлу…» читає такий файл і питає: **Об'єднати** (додати нові, оновити наявні,
застосувати видалення) чи **Замінити все**. Так можна передавати набір місць між користувачами: надіслали файл — інший імпортував.

### Як вивантажити файл обміну в репозиторій

**Спосіб 1 — без програм, через сайт GitHub (рекомендовано).**
1. Відкрийте репозиторій на github.com → тека `inbox/` → **Add file → Upload files**.
2. Перетягніть файл `mymaps-….json` (через веб-інтерфейс GitHub — до 25 МБ) і натисніть **Commit changes**.
3. GitHub Action «Імпорт файлу обміну з inbox/» запуститься сам (вкладка **Actions**): додасть і оновить картки в `data/`,
   стисне нові фото в WebP, перебудує `data/index.json`, перевірить каталог, закомітить результат і видалить файл з `inbox/`.
4. Через 1–2 хвилини GitHub Pages покаже оновлений каталог (оновіть сторінку).

**Спосіб 2 — локально.** `npm install`, потім `npm run import-bundle -- шлях/до/mymaps.json`, `npm run validate`, `git add -A && git commit && git push`.
Прапори: `--dry` (лише показати, що зміниться), `--mirror` (видалити з каталогу все, чого немає у файлі).

**Правила імпорту.** Картки зіставляються за `id` (старі id `d0…d24` — через `migration/slugs.json`), а нові створюються з читабельним slug із назви.
Фото, байти яких не змінились, лишаються без повторного стиснення; нові стискаються до WebP. Картки зі списку `deleted` видаляються.
Порядок беруть із файлу. Повторний імпорт того самого файлу нічого не змінює й не дублює.

**Обережно:** файл, експортований після видалення місць, видалить ці картки й з репозиторію. Імпорт — це «ваш список стає списком репозиторію».
Якщо файл більший за 25 МБ (багато нових фото), використайте Спосіб 2.

Старий `index.html` з вбудованими даними лишається в історії git. Вихідні дані на момент переходу на каталог збережено в
`migration/source/places.original.json.gz`; `npm run migrate` порівнює каталог з ними (повторний запуск нічого не дублює й не перезаписує наявні картки; `--force` перезаписує).
